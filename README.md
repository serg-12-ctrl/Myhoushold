# myhousehold# Backend-сервис «Менеджер домашних запасов»

Бэкенд-система для управления домашними продуктами и бытовыми товарами с учетом партий, сроков годности и продвинутых стратегий списания (FEFO/FIFO).

## Реализованный функционал
- **JWT-авторизация:** Регистрация, логин и получение профиля пользователя.
- **Учет партий:** Один товар может храниться в разных местах (холодильник, кладовая) и иметь разные сроки годности.
- **Движок списаний:** Поддержка стратегий `expires_first` (FEFO) и `oldest_first` (FIFO) с автоматическим каскадным распределением по партиям и транзакционными блокировками `select_for_update` (защита от Race Conditions).
- **Логирование:** Любое изменение остатка фиксируется в неудаляемом журнале операций.
- **Фоновые задачи (Celery + Redis):** Спроектированы задачи для ежедневной проверки просрочки и расчета прогноза окончания продуктов.

## Запуск проекта локально
1. Активируйте окружение и установите зависимости:
   ```bash
   .\myenv\Scripts\activate
   pip install -r requirements.txt
   ```
2. Примените миграции базы данных:
   ```bash
   python manage.py migrate
   ```
3. Запустите сервер разработки:
   ```bash
   python manage.py runserver
   ```

## Запуск тестов
Для проверки корректности бизнес-логики выполните:
```bash
python -m pytest
```

### Алгоритм прогнозирования расхода запасов (Раздел 7 ТЗ)
Прогноз строится на основе скользящего временного окна (`days_to_analyze`, дефолт — 14 дней):
1. Выбираются все исторические операции с типом `consume` за указанный период.
2. Проводится фильтрация аномальных выбросов: вычисляется медиана объема списаний, и все операции, превышающие 4 медианы, отсекаются для чистоты статистики.
3. Рассчитывается средний дневной расход по формуле: `V = Сумма_Расхода_За_Период / Количество_Дней_Окна` (что автоматически учитывает дни без расхода).
4. Оставшиеся дни жизни товара вычисляются как `Текущий_Остаток / V`.
5. Метрика `confidence` выставляется как `high`, если накоплено более 5 операций списания, иначе — `medium`. При нехватке данных возвращается статус `insufficient_data`.
